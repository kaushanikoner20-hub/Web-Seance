# Web Séance — Archaeological Methodology & Provenance

This document outlines the scientific methodology, data provenance, verification standards, and ethical guidelines governing **Web Séance**.

---

## 1. Research Principles

Digital archaeology investigates historical human culture through digital traces preserved in archival repositories. The early World Wide Web (1995–2005) represents one of the most culturally vital yet fragile eras of human expression.

Web Séance adheres to four core research principles:

1. **Traceability Over Plausibility**: A claim about an early webpage is valid only if it can be directly traced to verbatim archival markup or metadata. Plausible-sounding narrative generated by an AI model does not constitute historical evidence.
2. **Hygiene of the Artifact**: Historical HTML must be examined in its pristine state, purged of modern archival banners, tracking cookies, or proxy artifacts.
3. **The Non-Equivalence of Hyperlinks and Social Ties**: A hyperlink between two websites proves only that an author inserted an anchor tag. It does not establish that the owners were personal friends, members of the same organization, or agreed ideologically.
4. **Epistemological Humility**: When historical markup does not contain enough information to resolve a question, the correct answer is *"Insufficient evidence"*, not probabilistic speculation.

## 2. Archival Data Provenance

All historical web records in Web Séance originate from the **Internet Archive Wayback Machine**, the world's preeminent public repository of digital culture.

### 2.1 The CDX Index API
To identify historical captures without scraping, Web Séance queries the CDX Server API:
```
GET https://web.archive.org/cdx/search/cdx?url={TARGET}&output=json&fl=timestamp,original,statuscode,mimetype,digest,length&filter=statuscode:200&from=1996&to=2008&limit=5
```
- **Filter `statuscode:200`**: Discards redirects (301/302), missing captures (404), and server errors (500).
- **Temporal Bounding**: Restricts captures to the foundational web era (1996–2008).

### 2.2 Verbatim Replay via `id_` Modifier
When a standard Wayback URL (e.g., `https://web.archive.org/web/19981202/http://www.jwz.org/`) is loaded, the Wayback service injects:
- Modern CSS stylesheets (`/static/css/banner-styles.css`)
- Interactive JavaScript calendar toolbars (`/static/js/wombat.js`)
- Analytics tracking pixels

To preserve artifact hygiene, Web Séance requests the raw URL with the `id_` syntax:
```
https://web.archive.org/web/19981202075235id_/http://www.jwz.org:80/
```
The `id_` flag instructs the server to stream the byte-for-byte unmodified HTML stored in the original WARC/ARC record.

## 3. Link Extraction & Forensic Normalization

Extracted links undergo a deterministic 6-stage normalization pipeline in `core/html_extractor.py`:

```
Raw HTML Anchor: <a href="/projects/index.html:80#sec2">Projects</a>
      │
      ▼ Stage 1: Discard Non-HTTP Schemes (mailto:, javascript:, tel:, data:)
      ▼ Stage 2: Strip Anchor Fragments (#sec2)
      ▼ Stage 3: Normalize Default Port Artifacts (:80, :443)
      ▼ Stage 4: Resolve Relative Target against Base Capture URL
      ▼ Stage 5: Discard Wayback Machinery (/web/, archive.org/web/)
      ▼ Stage 6: Classify Scope (same_site vs. external)
      │
Result: http://example.org/projects/index.html (Scope: SAME-SITE)
```

### Forensic Hash Verification
Every raw HTML capture is fingerprinted using SHA-256 upon retrieval:
$$\text{ContentFingerprint} = \text{SHA-256}(\text{RawHTMLBytes})$$
This fingerprint is saved with the page metadata to guarantee non-repudiation and reproducible results.

## 4. The Evidence Schema

Every extracted link is stored in an immutable JSON structure:
```json
{
  "evidence_id": "P2-L3",
  "source_page_id": "P2",
  "source_url": "http://catb.org/~esr/",
  "destination_url": "http://www.opensource.org",
  "destination_host": "opensource.org",
  "anchor_text": "Open Source Initiative",
  "scope": "external",
  "capture_timestamp": "20030124110141",
  "archive_capture_url": "https://web.archive.org/web/20030124110141/http://catb.org:80/~esr/",
  "link_type": "hyperlink_in_archived_html",
  "extraction_method": "beautifulsoup4_html_parser",
  "ai_inferred": false
}
```

- `evidence_id`: Deterministic identifier combining Page ID and sequential Link ID.
- `ai_inferred: false`: Immutable flag denoting this record is an empirical archival fact, not an AI prediction.

## 5. Local AI Grounding & Citation Audit

When consulting `gemma3:4b` via local Ollama:
1. **Dossier Injection**: The model receives a text dossier containing exclusively the verified page title, timestamp, excerpt, and verified outgoing hyperlinks.
2. **System Prompt Constraint**:
   - The model must divide its output into **Confirmed Facts**, **Plausible Hypotheses**, and **Missing Information**.
   - Every factual assertion must cite an Evidence ID (e.g., `[P2-L3]`).
   - The model is explicitly forbidden from asserting interpersonal relationships between authors based solely on hyperlinks.
   - The model must output *"Insufficient evidence"* for unknown topics.
3. **Automated Citation Audit**:
   - After generation, `AIHistorian.validate_response()` runs regular-expression parsing on the output.
   - It cross-references every cited ID against the dossier's valid ID index.
   - Any hallucinated ID triggers a prominent warning in the user interface.
